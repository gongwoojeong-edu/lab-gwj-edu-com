> **독자**: 개발자, 강사, 신규 입사자
> **작성일**: 2026-05-10
> **버전**: v1.0

## 0. 이 문서를 읽는 법

이 문서는 단어학습기를 만들고 운영하면서 마주치는 모든 결정의 기준이다.

새 기능 요청이 들어왔을 때, 코드를 고칠지 말지 망설일 때, 사용자 피드백을
어떻게 반영할지 고민될 때 — 이 문서로 돌아온다.

**규칙**:
1. 이 문서와 충돌하는 결정은 하지 않는다
2. 이 문서를 바꿔야 할 만큼 큰 변화가 있다면, 그것 자체가 큰 의사결정이다
3. 외부 마케팅·블로그 콘텐츠 작성 시 이 문서에서 표현을 발췌한다

## 1. 우리는 왜 이걸 만드는가

공우정바른학원은 10년간 "태도가 실력이 되는 곳"이라는 슬로건 아래
학생을 가르쳐 왔다. 원장이 직접 강의하고, 시험 보고, 또 보고, 또 보는
**집요함**이 학원의 정체성이었다.

학생 수가 늘면서 그 집요함을 모든 학생에게 매일 적용하기 어려워졌다.
"한 번 더 시험 봅시다"를 원장이 직접 말하지 않아도, 시스템이 그 역할을
대신할 수 있어야 했다.

공우정 단어학습기는 그래서 만든다.

다른 학습기처럼 단어를 효율적으로 외우게 하는 도구가 아니다.
**원장이 한 사람 한 사람 끝까지 챙기던 방식**을 디지털로 옮긴 것이다.

따라서 이 학습기의 모든 결정은 다음 질문에서 출발한다:
> **"원장이 직접 가르친다면 이 상황에서 어떻게 했을까?"**

## 2. 핵심 원칙 5가지

이 학습기를 만들고 운영하는 다섯 가지 원칙.
새 기능을 추가할 때마다 이 다섯 가지에 부합하는지 검증한다.

### 원칙 1. 모르는 단어는 절대 놓아주지 않는다

학생이 한 번 틀린 단어는 시스템이 끝까지 추적한다.
- 단어 학습 → 인지 → 쓰기 → 테스트 4단계를 모두 통과해야 마스터
- 마스터한 단어도 일정 기간 후 재테스트
- 시험에서 또 틀리면 다시 1단계로 돌아간다

학생이 "이 단어는 외웠으니 됐다"고 생각하는 것을 시스템이 허용하지 않는다.
**완전히 자기 것이 될 때까지 시스템이 옆에서 떠나지 않는다.**

### 원칙 2. 끝까지 안 한 학습은 진도가 아니다

학생이 단어를 보기만 하고 테스트를 안 봤다면, 그것은 진도가 아니다.
다음에 같은 카드를 클릭하면 처음부터 다시 시작한다.

이는 "대충 훑고 넘어갔는데 진도는 나갔다"는 착각을 차단한다.
**진도란, 끝까지 통과한 것만을 말한다.**

### 원칙 3. 단어는 혼자 살지 않는다

다른 학습기는 단어를 단어 그 자체로만 다룬다.
공우정은 단어를 다음의 일부로 본다:
- 문장 안에서 (구문학습기와 연결)
- 글 안에서 (정독 자료와 연결)
- 발음으로 (EVT 발화 학습)
- 어원·다의어·품사 (입체적으로)

**단어를 외우는 것이 목적이 아니라, 단어를 살아있게 만드는 것이 목적이다.**

### 원칙 4. 학생은 자기 위치를 알아야 한다

매일 단어 20개씩 외우라는 말은 끝이 안 보인다.
학생이 지치지 않게 하려면 자기가 어디까지 왔고 어디로 가는지 보여줘야 한다.

- 책장별 마스터 진도
- 통합 어휘력 게이지
- 약점 단어의 학습 여정 (몇 번 틀렸고 지금 몇 단계인지)
- 누적된 학습일

**학생이 자기 성장을 매일 눈으로 본다.**

### 원칙 5. 사람이 시스템을 통제한다

운영 데이터는 SQL 없이 화면에서 다룰 수 있어야 한다.
- 잘못 부여한 특별과제는 클릭으로 삭제
- 잘못 입력된 마감일은 화면에서 수정
- 학생 데이터 백업·복구 도구
- 학습 데이터 검증 대시보드

개발자가 없어도 운영자가 시스템을 다스릴 수 있어야 한다.
**시스템이 운영을 결정하는 것이 아니라, 운영이 시스템을 결정한다.**

## 3. 다른 단어학습기와 무엇이 다른가

시중에는 이미 많은 단어학습기가 있다. 클래스카드, 일반 단어장 앱,
영단기, 능률닷컴 등. 그런데도 우리는 왜 새로 만드는가?

### 비교표

| 차원 | 일반 학습기 | 공우정 |
|---|---|---|
| 단어 처리 | 1단어 = 1뜻, 한 번 맞으면 통과 | 1단어 = {여러 뜻, 품사, 어원, 발음}, 4단계 모두 통과해야 마스터 |
| 학습 풀 | 단어 풀 단독 | 단어 → 구문 → 정독 → 발화 연결 |
| 약점 정의 | 틀린 단어 | 단어학습기에서 틀린 것 + 정독에서 막힌 것 + 발화 부정확한 것 |
| 통과 기준 | 한 번 맞으면 OK | 단어학습 → 인지 → 쓰기 → 테스트 (+ 재테스트) |
| 끈기 | 학생 스스로 | 시스템이 끝까지 추적 |
| 학습 위치 | 오늘의 진도 | 로드맵 안에서 내 위치 시각화 |
| 운영 | 콘텐츠 제공자가 결정 | 학원이 직접 다룸 |

### 핵심 차이 한 줄로

**일반 학습기는 "단어를 외우게" 한다.**
**공우정은 "단어를 살아가게" 한다.**

외우는 것은 일회성이지만, 살아가는 것은 반복적이고 입체적이다.
한 단어가 단어 학습에서 한 번 나오고 끝나는 게 아니라,
구문에서 다시 만나고, 정독에서 또 만나고, 시험에서 또 만나고,
발화 연습에서 또 만난다.

학생이 그 단어를 자기 영어의 일부로 받아들일 때까지 시스템이 데려간다.

### 우리가 절대 하지 않는 것

- **단어 셔플** — 학생이 끝까지 안 보고 통과하게 만드는 트릭
- **한 번 맞으면 통과** — "모르는 단어를 안다고 착각"하게 만드는 함정
- **단어를 단어로만 다룸** — 단어가 살아있게 하지 못함
- **게이미피케이션 중독 설계** — 도파민 사업이 아닌 교육

이런 기능 요청이 들어오면 거절한다. 다른 학습기가 한다고 해서
우리가 따라하지 않는다.

## 4. 학생 경험 (Student Experience)

학생이 매일 학습기를 켰을 때 어떤 경험을 해야 하는지 정의한다.
모든 화면 디자인과 기능 결정의 기준이다.

### 4.1 첫 진입 — "내 자리"가 보인다

학생이 로그인하면 가장 먼저 보이는 것:
- 오늘 학습할 것 (일반진도, 특별과제, 약점)
- 내 통합 어휘력 게이지
- 어제·그제 학습 결과 (변화가 보임)
- 연속 학습일

학생은 "어디서 시작해야 하지?"라는 고민 없이, 시스템이 권하는
오늘의 학습으로 자연스럽게 들어간다.

### 4.2 학습 중 — 단어가 자기 것이 되어가는 과정

한 단어를 만나면 다음 단계를 거친다:
1. **단어학습** — 뜻을 만난다
2. **인지** — 영어를 보고 뜻을 안다
3. **쓰기** — 뜻을 보고 영어를 쓴다
4. **테스트** — 종합 검증
5. (장기) **발화** — 입으로 나온다

각 단계마다 학생은 자신이 어디에 있는지 안다.
틀리면 다음 단계로 못 넘어간다. 다시 처음부터.

이 과정은 답답할 수 있다. 그러나 그 단단함이 공우정의 가치다.
"한 번 맞히면 통과"의 편안함이 단어를 잊게 만든다.

> **표현 사용 가이드**:
> 일반·내부용: "그 단단함이 공우정의 가치다"
> 마케팅 후킹용: "그 답답함이 공우정의 가치다" (의도적 도발)

### 4.3 약점 단어 — 시스템이 옆에 있다

학생이 어제 틀린 단어는 오늘 다시 만난다.
그제도 틀렸으면 더 자주 만난다.

학생은 화면에서 "이 단어는 4번째 만남이에요. 오늘 맞히면 마스터!"
같은 메시지를 본다. 자기가 한 단어와 어떻게 싸워왔는지 보인다.

이는 좌절이 아니라 **여정**이다. 그 여정이 끝나는 순간 효능감이 폭발한다.

### 4.4 진도 시각화 — 매일 자기 성장이 보인다

```
📖 essential L08    ████████░░ 80%
📖 박준언 고1       ███░░░░░░░ 30%
📖 약점 풀          ███████░░░ 70%
─────────────────────
🎯 통합 어휘력      ██████░░░░ 60% (805/1300)

연속 학습일: 7일 🔥
오늘 마스터: 5개 ↑
```

매일 학습 후 이 화면을 본다. 숫자보다 **변화**가 더 동기부여 된다.

### 4.5 학습기를 끄는 순간

학생이 오늘 학습을 마치고 학습기를 끌 때, 마지막으로 보는 것:
- "오늘 마스터한 단어 5개. 통합 어휘력 +0.4%."
- "내일 만날 단어 3개가 기다리고 있어요."

다음 만남을 예고하는 것. 끊김이 아니라 이어짐.

### 4.6 학생이 절대 보지 않는 것 / 우리 방식대로 쓰는 것

#### 절대 보지 않는 것 (학습 중 화면)
- **랜덤 셔플** — 단어가 무작위 순서로 나오는 것
- **건너뛰기 버튼** — 모르는 단어를 회피하는 통로
- **상시 점수 폭격** — 학습 중에 매 단어마다 점수·애니메이션이 터지는 것
- **학습 중 친구와의 비교 압박** — "친구가 너보다 앞서 있어요" 같은 실시간 비교

#### 우리 방식대로 쓰는 것

**랭킹·뱃지·시상은 사용한다. 단, 사용 방식이 다르다.**

##### 학습 중 화면 — 자기 인지 중심
학생이 단어를 외우는 동안에는 외부 자극을 끊는다.
보이는 것은 자기 자신뿐:
- "오늘 5개 마스터. 어제는 3개였어요" (어제의 나와 비교)
- "연속 학습 7일 🔥" (꾸준함 인정)
- "약점 10개 극복 뱃지 획득" (여정의 이정표)

##### 시상·랭킹 화면 — 학원 문화로서의 인정
학원에는 매달 시상 문화가 있다. 그 문화는 시스템이 지원해야 한다:
- 학년별 전체 랭킹 (기명, 월간)
- 시상 집계 자동화 (선생님이 손으로 안 세도록)
- 학습 누적·마스터 단어 수·꾸준함 등 다양한 기준

이는 **건강한 학원 문화**이지 **도파민 사업**이 아니다. 차이는:

| 차원 | 도파민 자극 | 공우정 시상 문화 |
|---|---|---|
| 빈도 | 상시 (매 클릭) | 의미 있는 단위 (월 1회) |
| 위치 | 학습 중 화면 | 시상 화면·게시판 |
| 목적 | 사용 시간 늘리기 | 한 달 노력 인정·축하 |
| 효과 | 자극 없으면 못 함 | 시상 없어도 학습은 계속 |

#### 시상 기준 6가지 — 다양한 방식의 노력을 인정한다

월간 시상은 단일 기준이 아니다. 학생마다 다른 방식으로 빛난다.
공우정은 그 다양함을 인정한다.

1. **종합 1등 (학년별)** — 학습 총점·전반적 성취
2. **꾸준함 상** — 연속 학습일이 가장 긴 학생
3. **마스터 누적 상** — 한 달간 마스터한 단어 수
4. **약점 극복 상** — 틀렸던 단어를 다시 정복한 개수
5. **안정적 학습 상** — 진도 흔들림 없이 꾸준히 나아간 학생
6. **특별 열심 상** — 원장·강사 재량 (수치로 안 잡히는 노력)

**이 6가지가 공우정의 메시지다**:
- 1등이 한 명이 아니다 — **6명의 다른 1등**이 있다
- 빠른 학생만 인정하지 않는다 — **꾸준한 학생, 흔들리지 않는 학생**도 1등이다
- 시작이 늦은 학생도 인정한다 — **약점을 극복한 학생**도 1등이다
- 수치로 안 잡히는 노력도 인정한다 — **재량 시상**으로 보장한다

**기술적 함의**:
- 시상 집계는 자동화되어야 한다 (선생님이 손으로 안 세도록)
- 6가지 기준이 모두 자동 추적 가능해야 한다
- "특별 열심 상"은 원장·강사가 화면에서 직접 지명할 수 있어야 한다

#### 핵심 원칙 (4.6 종합)

- **학습 중에는 자기 인지가 주인**, 시상·랭킹은 **별도 화면·시점**
- **속도가 아닌 끈기를 인정한다** — 빨리 푼 학생이 아니라 꾸준한 학생을 시상
- **다양한 기준의 시상** — 1등만이 아니라 다양한 방식의 노력을 인정

## 5. 선생님 경험 (Teacher Experience)

학습기는 학생만 쓰는 것이 아니다.
선생님이 매일 사용하는 운영 도구이기도 하다.
선생님 경험이 나쁘면 학원이 시스템을 끌어안지 못한다.

> **비전**: 단어학습기 v2는 단순 학습 도구가 아니라
> **공우정 학원 운영 OS**로 발전한다.
> 단어 → 단어·문법·독해 → 학원 운영 전반의 디지털 백본.

### 5.1 첫 진입 — 오늘 해야 할 일이 보인다

선생님이 로그인하면 가장 먼저 보이는 것:
- 오늘 출제할 학생 명단 (자동 출제 작동 중인지 한눈에)
- 어제 시험 채점 미완료 학생
- **특별 주의 학생** (약점 급증, 진도 흔들림, 결석 누적 등)
- **상담 필요 학생** (선생님이 직접 표시한 관리 대상)
- 약점 단어가 갑자기 늘어난 학생 (관리 필요 신호)
- 새로 등록한 단어책 검증 상태

선생님은 "오늘 뭐부터 해야 하지?"라는 고민 없이,
시스템이 권하는 우선 작업으로 자연스럽게 들어간다.

### 5.2 일일 수업 워크플로우

학원의 30분 단위 수업 운영을 시스템이 받친다:
- 4:00 학생 입실 + 숙제 제출 + **시간표 자동 출석 기록**
- 4:00~4:10 단어 핸드아웃 시험 (10분)
- 4:10~4:30 학습기 진도 (20분)
- 4:30~ 문법·독해

이 20분 동안 선생님은:
- 종이 시험지 채점 동시 진행
- 시스템에 점수 입력
- 별도 채점 시간 불필요

**시스템이 학원 운영 속도를 따라가야 한다.**

### 5.3 곤란한 학생 관리

모든 학생이 같은 속도로 가지 않는다.
선생님은 다음 학생을 표시하고 추적할 수 있다:

- **특별 주의 표시** — 진도 흔들림, 약점 급증, 결석 누적 등 시스템 자동 감지 + 선생님 직접 표시
- **상담 필요 표시** — 학부모 면담이 필요한 학생, 표시한 선생님이 누구인지·언제·왜 기록
- **관찰 일지** — 학생별로 짧은 메모 누적 (예: "5월 10일: 단어 학습 거부, 가정 사정 의심")
- **선생님 간 공유** — 한 학생을 여러 선생님이 가르치면 메모가 공유됨 (관리 일관성)

이는 **학원이 학생을 끝까지 챙기는 방식**의 디지털화이다.
원칙 1 "모르는 단어는 절대 놓아주지 않는다"는 학생에게 적용되고,
이 기능은 **곤란한 학생을 절대 놓아주지 않는다**는 그 옆에 있다.

### 5.4 데이터를 직접 다룬다

운영 중 발생하는 모든 사고는 화면에서 해결할 수 있어야 한다:

#### 학생 관리
- 잘못 등록한 학생 정보 수정·삭제
- 휴원·퇴원 처리
- 레벨 변경 (학년 진급 시)

#### 특별과제 관리
- 잘못 부여한 과제 즉시 삭제
- 마감일·메모 수정
- 일괄 부여 / 일괄 삭제

#### 단어책 관리

선생님이 단어책을 등록하는 경로는 다양하다. 시스템은 모든 경로를 받친다.
다만 어느 경로로 들어와도 **같은 데이터 정합성**을 보장한다.

**등록 경로 3가지**:

1. **자동 추출** (P1 기능)
   - 학습지 PDF/HWP/이미지 업로드
   - 영단어·품사·뜻 자동 추출
   - 미리보기 검토 → 수정 → 등록
   - 5분 안에 단어책 한 권 완성

2. **수동 입력** (UI 직접 입력)
   - 선생님이 화면에서 단어·뜻 한 줄씩 입력
   - 자동 추출이 어려운 경우 (사진 화질·특수 자료)
   - 소량 단어책·약점 모음·맞춤 단어책

3. **시드 입력** (대량 일괄)
   - SQL 시드 또는 CSV 업로드
   - 출판사 교재 전권 등록 등 대량 작업
   - 강사 분담 가능

**모든 경로 공통 보장 사항**:
- 같은 검증 절차 (P0 RPC `register_word_deck_with_words`)
- 같은 메타정보 표준 (level·deck_type·word.id 명명 규칙)
- 같은 트랜잭션 무결성 (실패 시 전체 롤백, 고아 단어 0건)
- 같은 사후 검증 (deck_words 개수 = 입력 N)

**등록 후 관리**:
- 잘못 등록된 단어 수정·삭제
- 덱 메타정보 변경 (레벨, 출판사, 시리즈 등)
- 덱 비공개 처리 (수업 종료 또는 잘못 등록 시)
- 덱 통합·분리 (예: 1~3과 따로 등록 → 한 권으로 합치기)

**학습된 교훈 — 입력 경로 다양성 ≠ 정합성 분산**:
박준언 고1 사고처럼 입력 경로 분산이 데이터 사고로 이어진 적이 있다.
그 교훈은 "입력 경로를 줄이자"가 아니라
**"어느 경로로 들어와도 같은 검증을 통과하게 하자"** 였다.
선생님은 자기에게 편한 경로를 자유롭게 선택한다.
시스템은 어느 경로든 같은 정합성을 보장한다.

#### 시상·랭킹
- 6가지 기준별 자동 집계
- 월말 한 번 누르면 시상 후보 자동 산출
- "특별 열심 상" 재량 지명

**개발자에게 SQL 부탁할 일이 없어야 한다.**

### 5.5 학부모 알림 자동화

선생님이 매주·매달 학부모에게 보내는 학습 요약을 시스템이 자동 생성한다:

- **주간 요약** (자동 발송 또는 선생님 검토 후 발송)
  - 이번 주 학습 단어 수, 마스터 수
  - 약점 극복 사례
  - 어제·지난주 대비 변화
  - 다음 주 목표

- **월간 리포트**
  - 한 달 학습 여정 타임라인
  - 시상 결과 (해당 시)
  - 학부모 면담 권유 (필요 시)
  - 같은 학년 평균 대비 위치 (익명)

- **즉시 알림** (필요 시)
  - 결석 누적 알림
  - 약점 급증 알림
  - 시상 수상 알림

**선생님이 매주 손으로 학부모 메시지 안 써도 되는 시스템.**
다만 발송 전 선생님 검토 가능 (자동화 = 사람 통제 불가가 아님).

### 5.6 학부모 상담 자료

선생님이 학부모와 상담할 때 시스템이 자료를 준비한다:
- 학생의 학습 여정 타임라인 (입학부터 오늘까지)
- 약점 단어 극복 사례
- 마스터한 단어 누적 그래프
- 같은 학년 평균 대비 위치 (단, 익명 평균)
- 한 달간 시상 기록

**학부모에게 "우리 아이가 이렇게 성장했어요"를 보여줄 수 있어야 한다.**

### 5.7 시간표 관리

학습기는 단어만 다루지 않는다. 학원의 시간표 운영도 받친다:

- **수업 출석 자동 기록** — 학생이 학습기 로그인 시점 기록
- **결석 자동 감지** — 수업 시간 후 일정 기간 학습 흔적 없으면 결석 표시
- **시간표 ↔ 학습 데이터 연결** — 어느 수업 시간에 누가 무엇을 학습했는지 기록
- **결석 누적 학생 자동 알림** — 5.1 "특별 주의 학생"과 연결

**30분 단위 수업 운영의 디지털 백본.**

### 5.8 다인 운영 (강사 분담)

학원에는 여러 선생님이 있다. 각자 권한과 역할이 다르다:

- **선생님 권한 분리** — 본인 담당 학생만 보거나 학원 전체 보기
- **시상 확정** — 강사가 후보 추천, 원장이 최종 확정 (재량 시상은 원장 전용)
- **시드 데이터 입력** — 강사 분담 가능
- **특별과제 부여** — 모든 선생님 가능, 단 본인 담당 학생만

**다인 운영을 시스템이 받쳐야 한다.**

### 5.9 선생님이 절대 마주치지 않는 것

- **SQL 직접 수정** — 무슨 일이 있어도 화면에서 끝나야 함
- **개발자 호출** — 운영 사고는 선생님이 해결
- **데이터 사라짐** — 운영 데이터는 절대 손실되지 않음
- **수동 집계** — 시상·랭킹·학부모 메시지는 자동, 손으로 안 씀
- **학생별 데이터 흩어짐** — 한 학생의 모든 정보는 한 화면에서 보임

## 6. 학부모 관점 (Parent Perspective)

학부모는 학습기를 직접 쓰지 않는다.
그러나 학원을 선택하고 유지하는 의사결정자다.
학부모가 보는 학습기는 **학원 신뢰의 척도**다.

### 6.1 학부모가 받는 메시지

학부모가 단어학습기를 통해 받는 것:

- **주간 학습 요약** — 이번 주 학습 단어, 마스터 수, 약점 극복
- **월간 리포트** — 한 달 학습 여정, 시상 결과, 평균 대비 위치
- **즉시 알림** (필요 시) — 결석, 약점 급증, 시상 수상

이 메시지의 목적은 **자랑**도 **변명**도 아닌 **투명성**이다.
학원이 "우리 아이가 무엇을 배웠고, 어떻게 성장하고 있는지"
숨김없이 전달한다.

### 6.2 학부모가 보는 것 — 자랑할 수 있는 데이터

학부모가 가장 보고 싶은 것은 **자기 아이의 성장 증거**다.
학원은 그 증거를 시스템으로 제공한다:

- **학습 여정 타임라인** — 입학부터 오늘까지 매일 학습 흔적
- **마스터 단어 누적 그래프** — 시간에 따라 어휘력이 어떻게 늘었는지
- **약점 극복 사례** — "이 단어는 5번 틀린 후 마스터했어요"
- **꾸준함 기록** — 연속 학습일, 빠진 날 수
- **시상 기록** — 한 달간 어떤 시상을 받았는지
- **같은 학년 평균 대비 위치** — 익명 평균 (다른 학생 정보 보호)

학부모는 이 자료를 친구·친척에게 자랑할 수 있어야 한다.
**자랑할 수 있는 학원**이 결국 추천받는 학원이다.

### 6.3 학부모가 보지 않는 것

- **다른 학생의 실명 데이터** — 개인정보 보호
- **학원 내부 운영 데이터** — 강사 메모, 곤란한 학생 표시 등
- **선생님 간 공유 메모** — 관찰 일지는 학원 내부용
- **상시 푸시 알림** — 부담 없이 천천히 받아볼 수 있게

### 6.4 학부모 상담 — 시스템이 자료를 준비한다

학부모와 면담할 때 선생님이 손으로 자료 정리할 필요 없다:

- 면담 직전, "학생 상담 자료 준비" 버튼 한 번
- 학습 여정 + 약점 극복 + 시상 + 평균 대비 위치 자동 출력
- 출력은 PDF (학부모가 가져갈 수 있게)

**상담 자료 준비 시간이 0이 되면 선생님이 더 자주 상담할 수 있다.**

### 6.5 신뢰의 메시지 — 공우정이 학부모에게 전하는 것

학부모가 단어학습기를 통해 받는 무언의 메시지 4가지 (우선순위순):

1. **"공우정은 우리 아이가 잊어버리지 않게 추적한다"**
   → 학원이 책임지는 학습. 학부모가 매일 단어 외웠는지 확인 안 해도 됨.

2. **"공우정은 우리 아이의 노력을 다양한 방식으로 인정한다"**
   → 시상 기준 6가지. 1등이 아니어도 빛날 수 있는 학원.

3. **"공우정은 시스템이 만들어낸 결과를 사람이 검토한다"**
   → 자동화로 효율을 높이되, 마지막 결정은 선생님이 한다.

4. **"공우정은 데이터를 숨기지 않고 보여준다"**
   → 학부모가 무엇을 배웠는지·어떻게 성장하는지 매주·매달 받는다.

이 4가지가 **"교육은 유행이 아닙니다"** 슬로건의 디지털 구현이다.

### 6.6 학부모 마케팅 활용

이 학습기는 학부모 마케팅 자료의 보고다:

- **블로그 콘텐츠** — "OO 학생, 6개월간 단어 1200개 마스터" 같은 케이스 스터디
- **상담 시연** — "다른 학원에 없는 우리만의 시스템" 차별화
- **수강 갱신** — 한 달 리포트가 갱신 결정에 영향
- **추천** — 자랑할 수 있는 데이터가 입소문 만듦

다만 **학생 개인정보는 절대 보호**한다. 익명·동의 기반으로만 활용.

## 7. 기술 결정의 기준

이 학습기를 만들면서 매일 기술 결정을 한다.
"이 라이브러리 쓸까? 이 기능 추가할까? 이 구조 바꿀까?"
모든 결정은 다음 5가지 기준을 거친다.

### 7.1 기준 1 — 학생 경험을 망치지 않는가

기술 결정의 1순위는 학생 경험이다.

다음 신호가 보이면 기술적으로 이득이 있어도 거부한다:
- 화면 깜빡임 (학습 흐름 끊김)
- 학습 중 인터넷 끊김으로 진도 손실
- 모바일에서 안 되는 기능 (학생은 핸드폰으로도 학습)
- 광고·외부 추적 코드

**예시**: "Google Analytics를 추가하면 사용자 분석이 정확해진다"
→ 학생 데이터를 외부로 보내는 것. **거부.**

### 7.2 기준 2 — 운영 데이터를 위협하지 않는가

운영 데이터(student, word_progress, student_decks 등)는 절대 손실되면 안 된다.
한 번 잃으면 학생 학습 이력이 사라지고, 학원 신뢰가 깨진다.

다음 작업은 신중하게 한다:
- DB 마이그레이션 (반드시 마이그레이션 스크립트 + 사후 검증)
- 컬럼 삭제 (먼저 deprecated 표시 → 충분한 기간 후 삭제)
- DELETE 쿼리 (where 절 두 번 검토, 백업 후 실행)
- 운영 환경 직접 접근 (시크릿 창 검증, 단계적 배포)

**예시**: "이 컬럼 안 쓰니까 DROP하자"
→ 다른 곳에서 참조 중일 수 있음. **사용처 전수 조사 후 deprecated → 삭제 단계화.**

### 7.3 기준 3 — 운영자가 직접 다룰 수 있는가

새 기능을 추가할 때 묻는다: "이 기능을 선생님이 SQL 없이 다룰 수 있나?"

다음 패턴은 거부한다:
- 데이터 수정에 SQL 콘솔 접근 필요
- 설정 변경에 코드 수정 필요
- 운영 사고 시 개발자 호출 불가피

새 기능 도입 시 반드시 따라오는 것:
- 운영 화면 (선생님이 직접 다룰 수 있는 UI)
- 검증 도구 (입력 직후 자동 확인)
- 복구 도구 (잘못 입력 시 되돌릴 수 있는 방법)

**예시**: "교과서 단어책 등록은 SQL 시드만 가능하게 하자"
→ 거부. 화면에서 등록·수정·삭제 가능해야 함.

### 7.4 기준 4 — 입력 경로 다양해도 정합성 통일되는가

선생님이 데이터를 입력하는 경로는 다양하다 (자동 추출, 수동 입력, 시드 입력).
어느 경로로 들어와도 같은 검증·같은 정합성을 통과해야 한다.

박준언 고1 사고에서 배운 교훈:
- 입력 경로가 분산되었는데 검증 절차가 분산되어 데이터 사고 발생
- 해결책: 모든 입력 경로가 같은 RPC를 통과하게 통일

새 입력 경로 추가 시 검증:
- P0 RPC (`register_word_deck_with_words`)를 통과하는가?
- 메타정보 표준을 따르는가?
- 트랜잭션 무결성을 보장하는가?
- 사후 검증을 자동 실행하는가?

**예시**: "구글 스프레드시트에서 단어 가져오는 기능 추가하자"
→ OK. 단, 가져온 데이터가 P0 RPC를 통과해야 도입.

### 7.5 기준 5 — 회귀 가능성이 통제되는가

코드를 고치면 다른 데가 깨진다. 그게 자연스러운 것이다.
중요한 건 **회귀 발견이 빠르고 복구가 쉬운가**다.

회귀 위험이 큰 작업:
- 광범위한 리팩토링 (한 번에 여러 파일 수정)
- 공통 함수·훅 변경 (사용처 전수 조사 필요)
- 데이터 모델 변경 (마이그레이션 + 코드 + 검증 동시 수정)

회귀 통제 방법:
- 시크릿 창 검증 (캐시 무효화)
- 단계적 배포 (부분 배포 후 모니터링)
- 커밋 단위로 작은 변경 (큰 PR 거부)
- git diff 직접 검증 (보고 ≠ 코드)

**예시**: "메인 화면을 5영역으로 개편하면서 인쇄 로직도 같이 고치자"
→ 거부. 두 번에 나눠서 각각 검증.

### 7.6 의사결정 트리

새 기능 추가 요청이 오면 다음 순서로 검증한다:

1. 학생 경험을 망치는가? → 망친다면 **거부**
2. 운영 데이터를 위협하는가? → 위협한다면 **마이그레이션 계획 + 백업 + 검증** 후 진행
3. 선생님이 직접 다룰 수 있나? → 안 되면 **운영 화면 동시 설계 필수**
4. 정합성을 통과하는가? → 안 되면 **P0 RPC 경유 설계 필수**
5. 회귀 위험은? → 크면 **단계적 배포 계획 필수**

이 다섯 단계를 모두 통과한 기능만 도입한다.
**"왜 안 되는가" 보다 "어떻게 해야 되는가"에 답할 수 있는 기능만 도입한다.**

### 7.7 기술 스택 결정

현재 기술 스택은 다음 원칙으로 선택되었다:

- **Vercel + Supabase + React** — 적은 운영 부하, 학원 규모에 맞는 인프라
- **TypeScript** — 컴파일 타임 검증으로 운영 사고 예방
- **Cursor (Claude)** — 모든 신규 작업의 메인 도구
- **시크릿 창 검증 의무화** — 캐시 무효화
- **git 커밋 단위 보고** — 보고 ≠ 코드 분리

기술 스택 변경 결정 기준:
- 학생 수가 100명을 넘었는가? (현재 7명 베타 → 학원 전체 → 공유 학원)
- 운영 부하가 임계치에 달했는가?
- 기존 스택에 명백한 한계가 있는가?

이 셋 중 하나도 해당 안 되면 **현재 스택 유지**.
"새 기술이 멋있어서" 같은 이유로는 변경 안 한다.

## 8. 하지 않을 것 (안티-패턴)

좋은 시스템은 "무엇을 하는가"만큼 "무엇을 안 하는가"로도 정의된다.
공우정이 의도적으로 거부하는 것들.
누군가 이 기능을 요청해도 이 섹션을 근거로 거부한다.

### 8.1 학습 콘텐츠 측면

#### 단어 셔플
다른 학습기들은 단어를 무작위 순서로 섞는다. "잘 외우게 하기 위해"라고 하지만,
실제로는 **학생이 끝까지 안 봐도 통과하게 만드는 트릭**이다.
공우정은 sort_order 순서로 학습한다. 한 권을 끝까지.

#### 한 번 맞으면 통과
"이 단어 알아요" 한 번 답하면 마스터 처리하는 방식.
학생이 **모르는 단어를 안다고 착각**하게 만드는 함정이다.
공우정은 4단계 (학습 → 인지 → 쓰기 → 테스트)를 모두 통과해야 마스터.

#### 단어를 단어로만 다루는 것
1단어 = 1뜻으로 다루는 것. 단어는 문장·문맥·발음·어원과 연결되어야 한다.
공우정은 단어를 구문·정독·발화와 연결한다.
**단어를 외우게 하는 게 아니라 단어를 살아가게 한다.**

#### 건너뛰기 버튼
"모르겠어요, 패스" 버튼. 모르는 단어를 회피하는 통로.
공우정은 모르는 단어를 만나면 멈추고 학습한다.
**모르는 단어는 절대 놓아주지 않는다.**

#### 진도와 학습의 분리
"학습은 했지만 시험은 안 봤다"를 진도로 인정하는 것.
공우정은 word_progress.status='완료' 만 진도.
**끝까지 안 한 학습은 진도가 아니다.**

### 8.2 동기부여 측면

#### 학습 중 도파민 폭격
매 단어마다 점수·애니메이션·소리. **사용 시간을 늘리는 트릭**.
공우정은 학습 중에는 자기 인지만 (어제의 나, 지난주의 나).
시상·랭킹은 별도 화면·시점에 분리.

#### 친구와의 실시간 비교 압박
"친구 김OO이 너보다 12등 앞섰어요" 같은 알림.
공우정은 **어제의 나와의 비교**가 학습 동력.
월간 시상은 학원 문화이지 실시간 압박이 아니다.

#### 속도 보상
"1분만에 푸셨어요!" 같은 빠른답변 뱃지.
공우정은 **속도가 아닌 끈기를 인정한다**.
빨리 푼 학생이 아니라 꾸준히 한 학생을 시상.

#### 단일 기준 1등만 시상
종합 1등 한 명만 인정하는 것.
공우정은 **6가지 다른 1등** (종합·꾸준함·마스터·약점·안정·재량).
다양한 노력을 모두 인정한다.

### 8.3 운영 측면

#### SQL 직접 수정
운영 데이터 사고 시 콘솔 SQL로 해결하는 것.
공우정은 **모든 운영을 화면에서 끝낸다**.
SQL 콘솔 접근은 마지막 수단이고, 이를 쓰는 시점이 곧 시스템 결함.

#### 개발자 호출
운영 사고 시 개발자가 와서 고쳐주는 구조.
공우정은 **선생님이 직접 복구할 수 있는 도구**가 핵심.
개발자가 없어도 학원이 돌아가야 한다.

#### 데이터 사라짐
운영 데이터가 손실되는 것. 단어, 학습 이력, 학생 정보, 시상 기록.
공우정은 **운영 데이터 절대 폐기 금지**.
컬럼 삭제 시 deprecated → 충분한 기간 → 마이그레이션 → 삭제 단계화.

#### 수동 집계
선생님이 매달 학생들의 점수·꾸준함·마스터 수를 손으로 세는 것.
공우정은 **자동 집계**. 한 번 누르면 6가지 시상 후보 자동 산출.

#### 입력 경로 정합성 분산
자동 추출·수동 입력·시드 입력이 각각 다른 검증을 거치는 것.
공우정은 **모든 입력 경로가 P0 RPC를 통과**.
어느 경로로 들어와도 같은 정합성.

### 8.4 비전 측면

#### 도파민 사업으로의 변질
사용 시간 늘리기, 중독 설계, 외부 자극 의존.
공우정은 **도파민 사업이 아닌 교육**.
"교육은 유행이 아닙니다" 슬로건의 반대편.

#### 과한 기술 투자
"새 라이브러리가 멋있어서", "AI 트렌드라서" 같은 이유.
공우정은 **현재 학원 규모와 운영 부하에 맞는 스택 유지**.
기술이 학원을 끌고 가지 않는다. 학원이 기술을 끌고 간다.

#### 학생 데이터 외부 노출
Google Analytics, 페이스북 픽셀 등 외부 추적 도구.
공우정은 **학생 데이터를 외부로 보내지 않는다**.
분석은 자체 시스템 내에서.

#### "다른 학원이 한다고 따라하기"
"클래스카드도 있으니 우리도 만들자" 같은 의사결정.
공우정은 **자기 철학에 맞는 것만 도입**.
시중 학습기를 쫓아가지 않는다. 다른 학원이 안 하는 것을 한다.

### 8.5 거부 시 답변 템플릿

이 섹션의 안티-패턴을 누군가 요청했을 때, 다음과 같이 답한다:

> "그 기능은 공우정 학습 철학과 맞지 않아 도입하지 않습니다.
> [철학 문서 §8.X]에 거부 이유가 정리되어 있습니다.
> 같은 목적을 다른 방식으로 달성하는 방법은 [대안] 입니다."

대안 예시:
- 단어 셔플 요청 → "sort_order 순서 학습 + 약점 풀 별도 메뉴"
- 한 번 맞으면 통과 요청 → "4단계 통과 + 재테스트 사이클"
- 도파민 폭격 요청 → "어제의 나와의 비교 + 월간 시상"
- 친구 비교 알림 요청 → "월간 시상 화면에서 학년별 랭킹"

**거부는 "안 한다"가 아니라 "다른 방식으로 한다"의 약속이다.**
