# 보류 문장 티칭 화면 (학생용, 승인 전)

## 의도 정리
보류(held)로 넘긴 문장은 학생이 이미 다음 문장을 학습 중이라, 티칭할 때 학생 화면에서 그 문장의 **원문 + 본인 해석**을 볼 수 없습니다. 승인 전에 학생과 함께 보면서 설명하고 → 그 뒤에 승인하는 흐름을 만듭니다.

## 만들 것: 학생 "첨삭 대기 문장" 화면

새 학생 페이지 `/learn/pending` (헤더/홈에 진입 버튼, 보류 건수 배지).

- 내 승인 이력 중 상태가 **held 또는 pending** 인 문장들을 목록으로 표시
- 각 카드에 지금 대기 화면에서 보이던 것과 동일한 내용:
  - 영어 원문
  - 내가 제출한 한글해석 (처음/최종이 다르면 둘 다)
  - 선생님 임시 메모(4칸 서식)
- **한글 정답(마스터 해석)은 표시하지 않습니다.**
- 여러 건이면 최신순 목록, 카드 하나를 크게 펼쳐 티칭용으로 볼 수 있게(선택된 카드 확대 표시)
- 실시간 구독: 선생님이 승인하면 해당 카드가 목록에서 사라지고 "승인 완료" 토스트

## 진입 동선
- 학생 홈(StudentHome) 상단에 "첨삭 대기 N건" 배너 → 클릭 시 이 화면
- 알림 벨 옆이 아니라 홈 배너 + 직접 URL 두 가지. 티칭 시 선생님이 학생 화면에서 바로 열 수 있습니다.

## 속도
- 이 화면에 들어갔을 때만 조회. 조회는 3건(승인목록 / 해당 문장 원문 / 내 해석)으로 배치 처리.
- 학습 화면·홈 로딩 경로에는 쿼리를 추가하지 않고, 배너 건수는 기존 알림/승인 카운트 훅과 동일한 가벼운 count 쿼리 1건만 사용.

## 기술 메모
- 신규: `src/pages/StudentPendingReview.tsx`, 라우트 `/learn/pending` (RequireAuth), 카운트 훅 1개.
- 데이터: `sentence_approvals`(status in pending/held, 본인 것) → `textbook_passages.code`로 english, `sentence_translations`로 처음/최종.
- 표시 컴포넌트는 기존 `SentenceReviewDetail` 재사용(원문/해석/메모), 메모는 `StructuredMemoView`.
- DB 변경 없음. RLS는 기존 본인 조회 정책 그대로 사용.
