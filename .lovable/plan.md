

## "분석 메뉴 어디 갔니" — 원인과 복구 계획

### 원인 (현재 상태)

분석 메뉴(=`AnalysisPanel`)는 **삭제된 게 아니라** 화면 우측 상단에 그대로 살아 있어요. 다만 최근에 헤더에 추가한 버튼들이 너무 많아져서 — `정답 입력` / `정답 저장` / `정답 초기화` / `AdminHintToggle` / `AI 단어 추출` / `단어 목록` / `진행 상태` / `사용자 메뉴` — **헤더가 두 줄로 wrap** 되었고, 결과적으로:

1. 데스크톱 우측 고정 분석 패널(`fixed top-[76px] right-4`)이 더 길어진 헤더 뒤에 일부 가려짐.
2. 헤더 우측 영역이 너무 빽빽해 **"분석 패널을 여는 시각적 단서"** 자체가 사라짐.
3. 새로 추가된 [AI 단어 추출] / [단어 목록]은 **선생님 전용 부가 기능**인데 정답 입력 관련 버튼들과 같은 줄에 평탄하게 나열되어, 본 흐름(분석)과 도구(추출 관리)의 구분이 사라짐.

### 복구 계획

#### 1. 헤더에서 선생님 도구를 "도구 그룹"으로 묶기 (`src/pages/Index.tsx`)

`AiExtractButton` + `ExtractedWordsPanel` + `AdminHintToggle` 세 개를 헤더의 별도 그룹으로 분리하고, 시각적으로 **구분선(divider)** 을 넣어 "분석 워크플로우(정답 입력/저장/초기화)" 와 "선생님 도구(AI/단어목록/힌트)" 를 분리.

```text
[정답입력 토글][정답저장][정답초기화]  │  [AI추출][단어목록][힌트]  │  [진행상태][사용자]
```

#### 2. 모바일/좁은 화면에서 도구 그룹을 ⋯ 메뉴로 접기

`md` 미만에서는 [AI추출][단어목록][AdminHintToggle] 세 개를 `DropdownMenu`(`⋯ 도구`)로 묶어 헤더 폭을 절약. 데스크톱(≥md)에서는 그대로 노출.

#### 3. 분석 패널 가시성 회복

- 우측 고정 패널의 `top-[76px]` → 헤더 실제 높이에 맞춰 `top-[68px]` 로 살짝 올리고, 헤더 wrap이 발생해도 패널이 안 가리도록 `lg:top-[var(--nav-h,76px)]` 패턴 대신 단순화: 헤더 자체를 한 줄에 맞도록 1번 작업으로 보장.
- 분석 패널 컨테이너에 옅은 보더/그림자 추가(`border border-border/60 bg-background/80 backdrop-blur shadow-lg`) 로 "여기가 분석 패널이다" 라고 더 잘 보이게.
- 데스크톱에서 단어 미선택 상태일 때 표시되는 "단어를 선택하세요" 안내 카드가 비어있다면, 패널 영역에 placeholder를 넣어 패널이 항상 시각적으로 점유하게 함.

#### 4. (보너스) 분석 패널 강제 토글 단축키

`?` 키 또는 우측 하단 작은 플로팅 버튼(데스크톱에서 패널이 안 보일 때만)으로 분석 패널을 강제로 다시 열 수 있게. 향후 또 가려지더라도 사용자가 즉시 복구 가능.

### 변경 파일

| 파일 | 변경 |
|------|------|
| `src/pages/Index.tsx` | 헤더 우측 영역 그룹화 + 모바일 ⋯ 도구 드롭다운 + 분석 패널 컨테이너 스타일 보강 |

### 동작 결과

- 1290px 뷰포트(현재 사용자): 헤더 한 줄 유지 → 우측 분석 패널이 다시 명확히 보임.
- 모바일: 도구 버튼이 ⋯ 안으로 접혀 헤더 깔끔.
- 학생 계정: 선생님 도구 그룹 자체가 안 보이므로 영향 없음.
- 기존 분석 로직/저장 흐름은 **전혀 건드리지 않음**.
